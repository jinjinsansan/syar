## 🔴 これを「着順が書き換えられた」と読んではいけない

★入力は全部 保存された値から組み直している:
   出走馬   { ...entrant_snapshot, horseId: String(gate) }   ← pg-store.ts:674-680 と同じ
   走路     conditionsFromFrozen(course_frozen, …)            ← pg-store.ts:704-709 と同じ
   種       races.server_seed
   絞り込み where scratched_at is null order by gate          ← pg-store.ts:636-639 と同じ

★final_seed は serverSeed ＋ raceId ＋ 馬番の一覧だけで決まる（settle.ts:59-60）。
  → ★どれも保存された値なので、★**種は当時と同じはず**。
  → ★残る変数は ★**エンジンのコードそのもの**。

★2026-08-20 以降、packages/race-engine と sim-engine に 28 コミット
  （D-065 の 2 次元走路と距離ロス／ES-5・ES-6 のレーン速度／K 0.22→0.237 …）。

→ ★★**説明として最も筋が通るのは「版の差」。★しかし断定できない。**
🔴 ★**断定できないこと自体が、★F-3 の穴**である:
   ★**どのレースを、どの版のエンジンが確定させたか、★どこにも記録が無い。**

## だから F-3 案③は、このままでは使えない
★再計算は「★同じ版どうし」でしか意味を持たない（★AU-21）。
→ ★**レースごとにエンジンの版を記録する**（★`races` に 1 列・★配備の識別子）か、
→ ★**「この版が確定させたレースだけを照合する」**形にするか。★裁定を仰ぐ。

⚠️ 本番は ★**0 本**が再計算可能（★entrant_snapshot が 0 件）。
   ★凍結を書く製品コードは 2026-09-19、★配備は 2026-08-20。
   → ★**いま在る 6,141 本は、★永久に照合できない。**
