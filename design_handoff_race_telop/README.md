# Handoff: レース カットイン C案「下三分の一テロップ」

## Overview
p4/race-30sec-cuts の「カットインのデザインが悪い」への回答。実装済みの `race-cutin.ts`（4種・全画面を金で拭いて覆う方式）を、**映像を止めない・隠さないテロップ形式**に置き換える提案です。

## なぜ全画面方式をやめたか
このプロジェクトは「カットが切り替わった瞬間に別のレースに見える」という問題と長く戦ってきました（`broadcast-v2.ts` の `fovRamp` / `frameContenders` / 各カメラの高さ統一など、すべて継ぎ目の不連続を潰すための調整です）。既存のカットイン実装は **1.2秒×4回、画面全体を不透明な帯で覆って中身に切り替える**構造で、これは製品が最も苦労して守ってきた「継続性」に、カットイン自身が新しい継ぎ目を持ち込んでしまう設計でした。C案はこの矛盾を解消します。

## この案の中身
- レース映像（既存の `drawObliqueWorld` 呼び出し）は**一切止めず、隠さない**。
- 画面下部・高さ104px（y432〜536）だけに**半透明の帯（テロップ）**がスライドして出入りする。
- 帯は既存の「実況の帯」（y560〜720）とは別の場所なので、両方が同時に出ても重ならない。
- 4種とも「金の台形タブ（種別ラベル）＋1〜2行の本体」という**同じ型**に統一。

## 4種の中身（情報は増減なし・帯の高さに収める形へ調整）
1. **A あなたの馬** — 枠札＋馬名（主役・52px）＋脚質・番手を1行
2. **B 現在の隊列** — 2Dの散布図をやめ、**横1本の位置バー**に変更（後方⇔先頭の線上に12頭の点、自馬だけ金・大きい）。「ビリヤードの玉」に見えるという指摘は、この形式ではそもそも起きません
3. **C ここから動く馬** — 元は最大4頭でしたが、帯の高さでは**最大2頭**が限度です。**要確認**（後述）
4. **D 最後の直線へ** — 番手と差を数字2つの1行に。2D コース図は帯の高さでは読めないため乗せていません

## オーナー確認が必要な点（2つ）
1. **背景の不透明さ**：元の要求は「背景は不透明」でしたが、この案では**帯の外（画面の86%）は常に映像が見えています**。帯自体は94%の濃さで読みやすくしていますが、画面全体を覆う仕様からの変更です。
2. **C（動く馬）の頭数**：元は最大4頭でしたが、帯の高さでは2頭が限度です。4頭を見せたい場合は、B・Dと同様に小さな別ウィンドウ（PinP）にする代替案も検討できます。

## 実装の指針
- `race-cutin.ts` の既存関数（`drawRaceCutInFrame` ほか）を**置き換えるのではなく**、新しい関数 `drawRaceTelop` を追加するのが安全です。世界の描画（`drawObliqueWorld`）は今までと同じタイミングで毎フレーム呼び続け、テロップはその**上に薄く乗るだけ**にします。
- 使う描画命令は既存と同じ制約内（`fillRect` / `fillText` / `beginPath`〜`fill`など）。斜めに切れたタブの意匠は `clip-path` ではなく、4点の `lineTo` で四角形を描けば同じ見た目になります。
- 出入りのアニメーションは、帯の y 座標を ease-out で下から上へ動かすだけです（`globalAlpha` のフェードは使っていません）。
