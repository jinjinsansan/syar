C案 — 下三分の一テロップ（映像を止めない）
v1〜v3の「全画面を金の拭きで覆う」構造をやめた。レース映像は最初から最後まで流れ続け、隠れるのは画面下部の帯だけ。この製品が最も苦労してきた「継ぎ目で別のレースに見える」問題に、カットイン自身が加わらないようにする設計。
帯の位置　　y432〜536（高さ104px）。y560〜720の実況帯とは別の場所に置き、両者が同時に出ても重ならない（実況が続いている最中にカットインが来ても両方読める）
キッカー　　帯の左上に金の台形タブ（幅230×高さ30、右辺だけ斜めに切る＝実際のテレビ中継のロワーサードと同じ作り）。「A自馬」等の種別ラベルをここに出す。clip-pathの斜め切りはCtx2DではlineTo4点の四角形で代替
出入り　　　v1〜v3の「中央から左右に拭く」は廃止。帯が画面の外（下）からy432まで100msでスライドし、1.0秒保持し、100msで下がる。fillRectのy座標をease-outで動かすだけ（globalAlphaは不要）
背景の透明度　帯自体はBAND色94%で実装（読みやすさ優先）。ただし帯が覆うのは画面の14%（104/720px）だけなので、映像の86%は常に見えている。元の要求「背景は不透明」は帯の中に限って維持し、画面全体には適用しない（この変更にオーナー確認を推奨）
A 自馬　　　枠札(72px)＋馬名52px＋脚質・番手を1行。v2までの主従設計（1つの主役＝馬名）を継承
B 隊列　　　2Dの散布図をやめ、帯の高さに収まる横1本の「位置バー」に置き換えた（後方⇔先頭の1本線上に12頭の点、自馬だけ金・大きい）。ビリヤードの玉批判はそもそもこの案では発生しない形式に変えている
C 動く馬　　最大2頭を1行で（先着側が主役サイズ）。4頭全部は帯の高さでは読めないため、情報量をこの帯に収まる範囲まで絞る調整が必要（オーナー確認事項として明記）
D 直線へ　　番手＋差を1行の数字2つで。ミニマップ（コース図）は乗せない——2D図は帯の高さ(104px)では読めないため、テロップ形式ではA/D同様「数字1行」に統一するのが妥当という判断
C案の代償　　映像を隠さない代わりに、B・Cは元の情報（2D隊列図・4頭リスト）を帯の形式に合わせて簡略化する必要がある。情報量を増やさない制約は守れるが、元の「4種の絵」を維持したいなら、B/Dだけ別の小さな別ウィンドウ（PinP）にする代替案もある（要相談）
実装　　　　race-cutin.tsのdrawRaceCutInFrameを置き換えるより、新関数drawRaceTelop（帯のみ描画・世界描画呼び出しへの介入なし）として追加するのが安全。既存のdrawObliqueWorldは今までと同じタイミングで毎フレーム描かれ続け、テロップはその上に薄く乗るだけ
