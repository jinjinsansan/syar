# レース参考映像再現 作業経緯記録

記録日: 2026-08-16  
対象: STAR レース画面  
参考資料: `ダービースタリオン/ダービースタリオン2025の２D参考用.mp4`

## 1. 目的と方針

参考映像の固有素材や文言を複製するのではなく、2D競馬中継としてのショット構成、カメラ方向、馬群の見せ方、背景の奥行き、ゴールまでの演出文法を分析し、STAR独自素材で再構築する。

最初に「完全再現できない理由」を調査した結果、単一の追走カメラや横向き素材の使い回しだけでは、参考映像にある方向別ショット、距離ごとの隊列差、コーナーと直線の構図変化を表現できないことが主要因と判明した。また、目視修正だけで機械的な比較・回帰判定がなく、一箇所の修正が別区間を壊しても検出できない状態だった。

このため、以下を実装原則とした。

- レース結果・位置計算と、映像上のショット選択を分離する。
- side / diag-front / diag-rear / rear / high-diagを別素材として扱う。
- ショットを純粋関数で決定し、Web表示とオフライン監査で共有する。
- 代表静止画だけでなく、全編を一定間隔で機械監査する。
- 短距離の寄りを維持しながら、長距離の縦長隊列へ画角を適応させる。

詳細計画はルートの`RACE_REFERENCE_REPRODUCTION_PLAN.md`に記録している。

## 2. 実装した基盤

### ショットシーケンサー

`packages/render/src/shot-sequence.ts`を追加し、以下のショット族を定義した。

- start-wide
- formation
- side-pack
- close-pack
- corner-wide
- corner-chase
- straight-wide
- finish
- winner

ショットごとにview、target、transition、カメラプリセットを持たせた。終了判定、残り距離、レース局面、表示時間から同じ入力に対して必ず同じショットを返す。

### 距離適応カメラ

固定画角では1600mを直すと3000mで後続馬が切れ、3000mへ合わせると1200mで馬が小さくなりすぎた。そのため終盤のcorner-chase、straight-wide、finishだけ、1600〜3000mの間でカメラ距離・高さ・FOVを連続補間する`shotCameraForDistance()`を追加した。

### 背景と透視投影

背景全面を地表色で初期化し、透視投影外の黒抜けを解消した。内馬場、細い管理路、二段ラチ、刈り筋、樹林、距離標識、照明塔をコース座標上へ配置した。注視地点をgate / backstretch / corner / homestretchへ分類し、直線の観客席、向正面の設備棟、コーナーの樹林密度を切り替えるようにした。

初期実装では全周の建築が別区間からも投影され、浮いた灰色帯になったため、注視地点前後の範囲だけを描画する方式へ修正した。樹冠も近景で巨大化したため、配置と画面上サイズを制限した。

## 3. 方向別馬素材

次のSTAR独自素材を制作・接続した。

- `horse-diag-front-v1`: 4位相×8枠色
- `horse-high-diag-v1`: 4位相×8枠色
- `horse-diag-rear-v1`: 4位相×8枠色
- `horse-side-v3`: 既存8コマから隣接セル断片を除去した修正版
- `horse-rear`: 既存の真後ろ8コマを継続使用

生成基準画は`design/race-assets/`、実働シートとメタデータは`apps/web/public/art/`へ配置した。方向別フレームの組立ツールと、セル境界へ漏れた連結成分を除去するクリーナーも`tools/`へ追加した。

## 4. 監査で発見した問題と修正

`tools/audit-race-broadcast.mjs`を作成し、distance / field / seed / stepを指定できるようにした。各ショット族の代表PNG、コンタクトシート、数値メトリクスを`out/reference-audit/`へ生成する。

監査では表示頭数、各馬の投影矩形、画面外切れ、馬群幅、平均馬幅を測定する。0.25秒刻みの全編に加え、浮動小数点刻みでは漏れる可能性があった厳密な最終時刻も必ず検査する。これによりwinnerショットが監査対象から欠落していた問題も修正した。

実際に検出・修正した主な問題:

- 1600mのcorner-chaseで後続馬が画面外へ出た。
- 2000mのfinishとstraight-wideで端の馬が切れた。
- 2400mのcorner-chase、straight-wide、finishで縦長隊列を収容できなかった。
- 3000mでは固定画角を広げるだけだと短距離の迫力が失われた。
- 最終フレームを監査しておらずwinnerショットの検証が抜けていた。

最終的に距離適応カメラへ変更し、短距離の馬サイズを保ちながら長距離だけ必要量引く構成にした。

5. 技術ゲート通過後に映像を目視判定する。

## 2026-08-17: 距離・頭数 HUD マトリクス

- 1200 / 1400 / 1600 / 2400 / 3000mを左右両回り、各12頭で監査し、全10条件で framing / motion / HUD遮蔽 failure 0を確認した。
- 6頭・1200mは左右とも合格した。
- 18頭・3000mの初回監査で、発馬1.25秒に馬番18が約306px飛ぶ不連続を検出した。
- 原因は馬の位置ではなく、スタートカメラが最後尾1頭を注視し、最後尾の入替時に注視レーンが切り替わることだった。

- 修正後の18頭・3000mは左右各588フレームでfailure 0。通常カット内最大移動は左17.7px、右17.5pxまで低下した。
- 注視対象の回帰テストを追加し、HUDを含む関連テスト12件と全体型検査に合格した。
