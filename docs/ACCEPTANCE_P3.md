## 10. ★V-10 の本番経路版 — a/b/c の3分解（Q-P3-34 の裁定）

> **裁定**: 払戻率の分散は「どのレースでどの目が当たったか」から来るもので、
> **同じレースに馬券を何枚買っても減らない。1レースあたりの標本は1つ。**

★**この分解を承認いただきました。成立条件を明記します。**

| | 中身 | 測り方 | 実測 |
|---|---|---|---|
| **a** | オッズが margin どおりか | ① `p × odds` | 全券種 **±0.36pt 以内**・上限に当たった目 0 |

### ★b は本番経路では測れません。移送しています

**b をハーネスで測った結果を本番に持ち込んでよい条件**は2つです:

1. **エンジンが同一であること**
2. **入力が同一であること**

```

・原本とバンドルの自己検査がバイト単位で一致 → エンジンが同一
```

### ★①②だけでは V-10 の証拠になりません

**この鎖の全体が証拠です:**

```
  a（①で厳密）
    ＋
  b（ハーネスで測定）── 移送 ──┐
                              ├── 能力比 1.0000 / 254-254 ＋ バイト一致 が licence
    ＋                        ┘
  c（②で厳密）
  ─────────────────────────────
  → 本番経路の V-10
```

### ★この licence は運用中に崩れうるので、定期的に確かめます（裁定）

> **R-23** は「コードが変われば失効する」でした。**これは「ある性質が崩れたら失効する」**です。
> そしてその性質は**運用中に崩れます**。

実際、この便で**2回崩れました**:

| いつ | 崩れ方 |
|---|---|
| ②③ 投入前 | `PLACEHOLDER_UNLOCK` により能力比 **2.2754倍** |
| 配備直後 | `loadTrainingStates` が週送り未通過の馬を返さず、**224頭全部で調子がずれた** |

★**どちらもコード変更ではなく「本番のデータの状態」で崩れました。**
だから **`tools/diag-b6.mjs` の per-horse 照合を、定期的に流すものとして扱います。**

```bash
npx tsx tools/diag-b6.mjs      # ★b の licence が生きているかの確認
```

⚠️ **平均で見てはいけません。** 224頭全部がずれていたとき、
生成側 `rng.int(2,4)`（平均3）と確定側の既定値 `3` は**平均が一致していました**。
**照合は、壊れ方と同じ粒度で行うこと**（正典 R-22）。

★**a と c だけを示して「V-10 は本番経路で確認済み」と書いてはいけません。**
それは「オッズ表の内部整合」と「払戻の機械」を示しただけで、
**推定確率がレース過程に対して正しいか（b）は何も言っていません。**
b が移送できなくなったら（＝能力比が 1.0000 でなくなる／バンドルが原本と食い違う）、
**V-10 はその時点で未証明に戻ります。**
