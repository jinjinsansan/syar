## 1. ★寸法 — 32×32 では成立しませんでした

### 経緯

| # | やったこと | オーナーの評価 |
|---|---|---|
| 1 | 細密画を 32×32 に**機械的に縮小** | ★「ぼやけており、何かわかりません」 |
| 2 | **最初から 32×32 のドット絵**として描かせた（12色・輪郭立て） | ★同じく不可 |
| 3 | 32/48/64/96/128px を並べて比較 | 「馬に見えるのは **96 と 128**」 |
| 4 | ★**実際のレース画面**（1280×720）で A=350 / B=220 / C=140 | **A・B 可 / C 不可** |

### ★学んだこと

**「作り方」の問題ではありませんでした。** 32×32 に馬と騎手を入れると**輪郭以外は原理的に消えます**。
アートバイブル §3 の「32×32 では馬体で描き分けられない」が、**絵全体に対して起きていました**。

★**そして「絵単体」を見せている間は決まりませんでした。**
**実際のレース画面（何頭映るか）を作って初めて**、オーナーが判断できました。
→ **判断材料は「部品」ではなく「使われる場面」で作る。**

### ★「エンジン側の契約が動く」は実体がありませんでした

D-057 は「32×32 を変えるとエンジン側の契約が動く」としていましたが、機械で確かめると:

```
描画層         : 寸法を一切持たない（grep 0件）。シート名＋フレーム番号で参照
レースエンジン : 絵を知らない（着順と時間だけ）
依存していたもの: ★文書だけ
```

→ レビュー側が誤りを認め **D-058** で撤回。**§12.8 の描画抽象化を先に入れていたから、結合が無かった**ものです。

## 2. ★ゼッケン — 5回作り直しました

**ここが最も時間がかかりました。** 毎回オーナーの指摘が具体的だったので直せています。

| 回 | 作り方 | 指摘 | ★原因 |
|---|---|---|---|
| 1 | SVG の矩形＋ベクタ文字を**上から貼る** | 「クオリティが悪すぎる」 | ★**ドット絵の上に別種のものを貼っていた**（アンチエイリアス・粒度が違う） |
| 2 | 画素で描いた札を貼る | 「実際の馬のゼッケンを見て」 | ★**位置が肩の上**。実物は**鞍の下・胴の側面**で、**騎手の脚が前に重なる** |
| 3 | 生成側に白い布を描かせ、色と番号を塗る | 「まだ頑張って欲しい」 | ★**布が小さく、数字が 3×5 で粗い** |
| 4 | 布を大きく・数字を 5×7 に | 「数字が大きすぎる／書体が揃わない／布感がない」 | ★**布いっぱいに描いた**／**線の太さが1画素と2画素で混在**／**べた塗り** |
| 5 | 余白・書体統一・布の階調 | 「2・5・8・11 だけでかい」「まだプラスチック」 | ★**馬ごとに倍率を計算していた**／**なめらかな階調** |
| **6** | **共通倍率・段の階調・縁取り・折り目・裾の揺れ** | **OK** | — |

### ★得られた原則

| # | 原則 |
|---|---|
| 1 | **ゼッケンは UI ではなく「馬に付いている物」**。絵の一部として同じ画素の粒度で描く |
| 2 | **装具は生成側に描かせる**。後から貼ると、騎手の脚との重なりが作れない |
| 3 | **書体は「線の太さと字幅が揃っているか」で決まる**。字形の巧拙ではない |
| 4 | ★**ドット絵の布は「段の階調」。連続した階調はプラスチックに見える** |
| 5 | ★**輪郭を崩すほうが、陰影を足すより効く**（真っ直ぐな下端は布に見えない） |
| 6 | **折り目は 2画素幅の帯**。1画素の線は「傷」に見える |
| 7 | ★**縁取り（トリム）がいちばん効く**。実際のゼッケンは縁に帯がある |

### ★1度やりすぎました

裾の揺れを**振れ幅3〜4画素・細かい周期**で入れたら、**ギザギザの歯**になり「破れた布」に見えました。
→ **最大2画素・ゆるい周期**に。**「揺れる」のであって「欠ける」のではありません。**

★**拡大して自分で見たから気づきました。** 全体表示では変化が小さく見え、そのまま報告していたはずです。

## 3. ★実際の競馬を調べた結果

**色だけで18頭を区別しているのは、実際の競馬でも成立していません。**

| 層 | 内容 |
|---|---|
| 1 | **勝負服** — 馬主が登録する固有の意匠。同じものは2人と使えない |
| 2 | **ゼッケンの色** — ★**枠順で決まる標準色**（1=赤 / 2=白 / 3=青 / 4=黄 …） |
| 3 | **番号** — ゼッケンと腕章 |

★**実際の18色を測ると最小距離 27.5**（灰と淡青）で、**目安の30に届いていません**。

```
実際の競馬の18色   : 27.5  ★足りていない
私が機械で選んだ18色: 34.0
```

→ **実際の競馬も「色だけでは足りない」前提で、番号を併用しています。**
★**アートバイブル §4「色だけで意味を運ばない」そのもの**でした。文書にそう書いてあったのに、
私は色だけで解こうとしていました。

### ★憲法との線引き

| | |
|---|---|
| ✅ 採った | **枠順ごとのゼッケン色と番号**という**業界共通の作法** |
| ★採らない | **実在の馬主・団体の勝負服の意匠**（憲法 §0.1・アートバイブル禁止事項1） |

★騎手の服は**生成した無地**のままで、実在の勝負服は一つも模していません。
**業界共通の作法をどこまで採ってよいかは憲法の解釈**なので、レビュー側に照会中です。

## 4. ★色の選び方は機械でやること

18色を目で選んだところ、**濃い黄色と薄いレモン色**が混ざり、オーナーに一目で指摘されました。

★**18色の組み合わせは153組**あります。**人が見比べる数ではありません。**

| | 前 | 後 |
|---|---|---|
| 選び方 | 目で選ぶ | ★**いちばん近い2色の距離を最大化** |
| 距離の測り方 | — | ★**CIE Lab**（RGB は人の見え方と一致しない） |
| 除外 | — | ★**芝の緑・馬体の茶に近い色**（背景に溶ける） |

★**平均距離ではなく「いちばん近い2色」を最大化**します。
平均が良くても**1組だけ近ければ、その2頭は見分けられません**。

## 6. ★制作経路（指示書 A-1 からの逸脱）

| | |
|---|---|
| 指示 | アセットは `image-cockpit-for-codex-workflows` で作る |
| 実際 | ★**Codex CLI を直接叩いた**（オーナーのご提案） |
| 理由 | cockpit の画面が **`二足（biped）固定・セル 256×256 固定`** で**馬（四足）に合わず**、生成物を outbox に置けない不具合も続いた |
| 同じ点 | **生成エンジンは同一**（Codex の imagegen） |
| 補い | ★**プロンプト全文をコミット**（A-2 の目的＝出所の記録は満たす） |

★**この逸脱で回避できた問題**もあります — cockpit のアニメーションは biped 固定でした。

### 環境で踏んだもの（次回のため）

| # | 症状 | 原因と対処 |
|---|---|---|
| 1 | `Cannot start service: Host version ... does not match` | ★cockpit が **Linux で `npm install` されたまま**で Windows 用 esbuild が無い → cockpit 側で `npm install` |
| 2 | `spawn ~\AppData\Roaming\npm\codex ENOENT` | 拡張子なしの `codex`（Unix 用）を Windows で spawn していた |
| 3 | `spawn EINVAL` | ★**`.cmd` は Node 18 以降 直接 spawn できない** → **`codex.exe` 本体**を指定 |
| 4 | `CreateProcessAsUserW failed: 1312` | ★**画像は生成できるがコピーできない**（Windows サンドボックス）→ `tools/codex-imagegen.mjs` が拾う |

★4 は毎回起きるので**道具にしました**。`~/.codex/generated_images/` の**実行前後の差分**で拾い、
**2件以上あったら選ばずに止まります**（取り違えると別の絵を「これです」と報告することになるため）。

## 8. ★測り方で間違えたこと（記録）

| # | 誤り | どう気づいたか |
|---|---|---|
| 1 | 勝負服を**彩度**で見分けた | ★**鹿毛の茶（彩度 0.57）を勝負服として数え**、126画素＝不透明部の48%という**多すぎる値**で気づいた → **色相**で測り直し |
| 2 | セルを**正方形（220×220）**で測っていた | D-058 は **220×140**。縦横を分けた |
| 3 | **接地線が 13px ずれていた** | ★毎回測っていたので出た。フレームごとに余白を詰めていたため → **下端を揃えて 0px** |
| 4 | 布の検出が**騎手の白いズボン**まで拾っていた | ★番号が切れた → **いちばん大きな「ひと繋がりの塊」**だけを布とする |
| 5 | 布の外接矩形から倍率を計算 | ★布は**長方形ではない**ので角がはみ出た → **実際に置いて収まる倍率**を選ぶ |
| 6 | 倍率を**馬ごとに**計算 | ★「2・5・8・11 だけでかい」→ **全馬共通**にし、**18頭すべてで置けることを確かめてから**決める |

★**3・4・5 は事後条件を入れていたから見つかりました。** 入れていなければ、
**接地線がずれた／番号が切れた**まま「できました」と報告していました。
